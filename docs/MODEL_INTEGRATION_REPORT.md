# 彩绘佛像 GLB 接入报告

## 结果

当前网页已实际加载并渲染彩绘佛像 GLB，不再以图片或平面替身冒充模型。模型被内嵌进离线单文件 `index.html`，运行时不发起远程资源请求。

本轮又核验了用户提供的“敦煌佛像数字展示-完整项目”并移植其彩色外观。该目录里的 GLB 实际是无材质白模，所谓彩色效果来自 `buddha.html` 的运行时位置分区 Shader；因此没有用白模覆盖现有资产，而是在当前更完整的 v3 GLB 上复现同一套青蓝、朱红、赭黄、肤色、发色、青绿与金色规则。

施工阶段仍保留原程序化佛像，以承载开凿、木桩、敷泥、收光等依赖专用几何属性的动画；完成态使用导入的 GLB：

- `0.0–16.2s`：导入模型完成态，随后随原镜头淡出。
- `31.0–90.19s`：程序化模型承担施工动画。
- `90.2–93.0s`：导入模型由素胎色自上而下显现位置分区彩绘。
- `93.0–116.373s`：导入模型完成态。
- GLB 解析失败时自动回退到程序化佛像，避免画面空缺。

- 来源白模：`buddha-standing-white.glb`

- SHA-256：`a4f5cd1f679ae7478ed41805bd851ab4aa6a89d0dfa8f4710d66474073fd9ad2`

- 数据仅有 `POSITION` 与索引；没有法线、`COLOR_0`、UV、材质、纹理或动画
- 主体 `POSITION` 与 indices 和当前 v3 主网格逐字节一致

- 实际采用：保留 v3 法线、顶点色数据与白毫节点，停用旧顶点色渲染乘法，移植演示页的 `buddha-smooth-garment-v2` 位置配色逻辑

## 已知视觉边界

导入资产本身是站立佛像，而参考视频中的洞窟主尊更宽、更接近倚坐巨佛。因此本次解决的是“真正使用用户指定的彩绘三维模型”，不是对历史造像姿态和比例的完全还原。若要继续提高参考片一致性，需要换成姿态、衣褶、手印和身宽都匹配的坐佛 GLB，或在建模软件中重塑当前资产。

自动化使用 x64 Node 经 Rosetta 驱动 SwiftShader 软件渲染，本轮冷启动记录为桌面约 71.6 秒、390×844 约 32.7 秒、604×816 DPR2 约 17.4 秒；该数据明显受到测试环境降级警告影响，不能当作真实设备性能结论。模型本身有 342,684 个三角形，弱移动设备仍存在加载与帧率风险。
