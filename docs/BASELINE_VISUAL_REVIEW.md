# 基线视觉否决报告

## 结论

当前 `d1b1ffa` 基线不满足用户唯一硬性标准“视觉效果非常惊艳”，也不满足“尽量 100% 还原整个石窟制作过程”。虽然源码包含 Three.js 场景、116.4 秒时间轴和 16 个章节，但 30 个关键时间点截图显示，画面仍接近粗糙静态示意图。

## 实测证据

- 已成功生成单文件 HTML，约 1.37 MiB。
- 已在 1、4、8、13、17、21、26、28、33、35、41、45、49、53、57、60、64、69、74、79、84、88、91、94、97、104、107、110、114 秒生成截图。
- 关键帧合成图保存在本地 `mogao-evidence/baseline-contact.jpg`，未进入 Git。
- 1、60、116 秒浏览器冒烟检查成功，未出现阻断性 console error / pageerror。
- 116 秒渲染统计：389 draw calls、642,610 triangles、325 geometries、37 textures。
- 浏览器报告两条截图 ReadPixels 引起的 GPU stall 警告；这是截图读取路径的性能警告，不等同于生产帧率验证。

## 阻断性视觉问题

1. **镜头穿模与错误构图**
   - 1 秒九层楼构件遮挡佛像。
   - 13 秒镜头几乎贴进佛像裙摆。
   - 多个洞窟镜头被崖壁平面或横向结构遮挡。
   - 97–107 秒相机过近，壁面变化和空间关系不清楚。

2. **主体造型失真**
   - 大佛头身比例、肩臂、手掌、衣褶和足部接近低模卡通。
   - 头光中央出现异常穿孔/遮挡，严重破坏面部识别。
   - 面部细节依赖贴片和简单线条，缺少参考视频的庄严体量和柔和塑像质感。

3. **崖壁与洞窟缺乏体积**
   - 崖壁大面积近似平面米黄色纹理。
   - 洞口和拱顶主要表现为几块平板/矩形切口。
   - 开凿阶段没有可感知的连续体积移除，石胎也不是从岩芯中逐步显露。

4. **施工动作不可读**
   - 栈道只有细小构件出现，缺少梁、柱、板、支撑的有序搭建。
   - 窟门、拱顶和上下开凿没有工具撞击、粉尘、裂纹传播、落石和堆积反馈。
   - 木桩阶段只有静态黑杆，没有逐根钻孔和敲入动作。
   - 泥塑阶段大多是整体材质/形体切换，表面传播、湿润感、开裂、纤维和逐层加厚不明显。
   - 上色与壁画阶段接近全局淡入，缺少刷涂方向和局部完成过程。

5. **材质与光照廉价**
   - 漫反射颜色过平，缺少细尺度凹凸、粗糙度差异、边缘积尘和湿泥高光。
   - 天空、崖壁、洞内与佛像的色温关系不统一。
   - 缺少体积光、空气透视、粉尘层次和可信接触阴影。

6. **交互叙事不足**
   - 章节按钮只能跳到时间点；用户点击后没有明确的“本步骤开始—进行—完成”反馈。
   - 画面变化小，导致用户即使点击步骤也会认为仍是一张图片。

## 必须达到的修正下限

- 每个章节至少包含一种明确几何动作和一种环境反馈。
- 开凿、泥塑、上色和壁画必须采用可见的空间/表面传播，不允许只做整体淡入。
- 所有关键镜头都要做遮挡、穿模和主体占屏比检查。
- 大佛头光不得遮挡或穿透面部。
- 用户不读字幕时也能判断当前施工语义。
- 关键时间点截图需与本报告逐项对比，通过后才能讨论“惊艳”。
